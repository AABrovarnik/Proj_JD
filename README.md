# ЮрОтдел — локальный MVP

Локальный прототип веб‑приложения для первичного анализа договоров аренды по ТЗ.

## Что реализовано

- Вход в систему (локальный admin).
- Отдельные страницы: `Анализ` и `Настройки`.
- Настройки профиля анализа (сторона, лимиты, дополнительный промпт).
- Выбор LLM-провайдера: `OpenAI` / `Alice` / `Local Mock`.
- Хранение выбора провайдера и модели в `settings`.
- Ввод API-ключей в защищённых полях на странице `/settings`.
- Зашифрованное локальное хранение ключей в `data/secrets.enc.json` (AES-256-GCM).
- Загрузка PDF/DOCX.
- Извлечение текста из PDF/DOCX.
- Анализ через выбранный LLM-провайдер (или локальную эвристику).
- Строгая JSON Schema-валидация результатов LLM на сервере.
- Уточняющий режим: 1 базовый + до 4 дополнительных раундов по проблемным параметрам.
- Хранение результатов и аудит в `data/db.json`.
- Экспорт результатов в JSON и CSV.
- Страница сравнения сильной и бюджетной моделей: `/compare` (по договорам и параметрам).
- Предложение улучшения дополнительного промпта от сильной модели для следующего прогона бюджетной.

## Рекомендуемые пары LLM (сильная/бюджетная)

- Вариант A (стабильный):
  - Сильная: `openai / gpt-6.1-sol`
  - Бюджетная: `openai / gpt-6-luna`
- Вариант B (гибрид):
  - Сильная: `openai / gpt-6.1-sol`
  - Бюджетная: `alice / <ваша бюджетная модель в Alice>` (если нужен гибридный контур)

Примечание: названия моделей Alice зависят от вашего контура/аккаунта, поэтому в `.env` оставлены как настраиваемые значения.

## Настройка LLM через `.env` и страницу настроек

Скопируйте шаблон:

```bash
copy .env.example .env
```

Заполните значения в `.env`:

```env
OPENAI_API_KEY=...
ALICE_API_KEY=...
ALICE_API_URL=...   # URL endpoint Alice API
```

Примечания:
- Для `OpenAI` используется `POST https://api.openai.com/v1/responses`.
- Для `Alice` используется `ALICE_API_URL` (ожидается OpenAI-like ответ с `choices[0].message.content` или поле `output_text`).
- Ключи можно сохранить через страницу `/settings`: они не отображаются повторно и не отдаются API в открытом виде.
- При запуске анализа используется приоритет: значения из `.env` → если пусто, берутся сохранённые зашифрованные ключи.
- Если ключ/URL не заданы, анализ вернёт понятную ошибку по документу.

## Ограничения текущей версии

- OCR для сканов не включён (нужен отдельный модуль Tesseract/Surya).
- Нет фоновой очереди worker и многоарендности.
- Полная защита от prompt-инъекций в документе требует отдельного набора интеграционных тестов на боевых моделях.

## Запуск

1. Установить Node.js 20+.
2. В каталоге проекта выполнить:

```bash
npm install
npm run start
```

3. Открыть:
- `http://localhost:3000/` — анализ;
- `http://localhost:3000/settings` — настройки.
- `http://localhost:3000/compare` — сравнение сильной и бюджетной моделей.

4. Логин по умолчанию: `admin` / `admin123`.

5. Перед передачей результата прогнать preflight:

```bash
npm run preflight
# при запуске на другом порту:
# BASE_URL=http://localhost:3101 npm run preflight
```

## Основные файлы

- `src/server.js` — API и маршруты страниц.
- `src/llm.js` — интеграция провайдеров LLM.
- `src/schema.js` — JSON Schema-валидация ответов модели.
- `src/extract.js` — извлечение текста.
- `src/analyzer.js` — локальный mock-анализ.
- `src/storage.js` — JSON‑хранилище.
- `public/index.html`, `public/analysis.js` — страница анализа.
- `public/settings.html`, `public/settings.js` — страница настроек.
- `public/styles.css` — общий UI-стиль.
