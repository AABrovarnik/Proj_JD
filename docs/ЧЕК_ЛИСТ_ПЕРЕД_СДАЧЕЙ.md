# Чек-лист перед передачей результата

Использую этот список **перед каждым "готово"**.

## 1) Среда и порт
- [ ] Проверить, что сервер запущен именно из текущего проекта.
- [ ] Проверить, что нужный порт свободен/контролируем.
- [ ] Если порт занят чужим процессом — согласовать с пользователем перенос на другой порт.

## 2) Синтаксис и базовая работоспособность
- [ ] Прогнать `npm run preflight`.
- [ ] Убедиться, что нет ошибок синтаксиса в `src/server.js` и `public/settings.js`.
- [ ] Проверить, что `/api/auth/login` возвращает JSON с токеном.

## 3) Ключевые API после изменений
- [ ] Проверить новые/изменённые эндпоинты (структура JSON, не HTML).
- [ ] Для секретов: `/api/secrets/status` и `/api/llm/profiles`.
- [ ] Проверить негативный кейс (например, пустой payload там, где должен быть 400).

## 4) UI-проверка
- [ ] Проверить, что целевая страница открывается на актуальном сервере.
- [ ] Проверить, что новые элементы интерфейса видны и работают.
- [ ] Проверить, что стиль/верстка не сломаны.

## 5) Передача результата пользователю
- [ ] Указать, где именно доступны изменения (порт/URL).
- [ ] Явно сообщить, что проверено лично и что осталось на стороне пользователя.
- [ ] Если есть ограничение среды (доступы/чужой процесс), указать его прямо.

## Быстрый запуск preflight
```bash
npm run preflight
# при проверке альтернативного порта:
# BASE_URL=http://localhost:3101 npm run preflight
```
