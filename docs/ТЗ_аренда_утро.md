Техническое задание на WEB‑приложение для ИИ‑анализа договоров аренды
1. Назначение и цель системы
Цель: автоматизировать первичный анализ договоров аренды для юридического отдела: быстро выявлять наличие/отсутствие ключевых параметров, оценивать качество договора и подсвечивать риски.

Задачи:

Извлекать из договоров (PDF/DOCX) ключевые параметры, специфичные для аренды.
Проверять наличие/отсутствие каждого из заданных параметров с детализацией (цитаты, разделы).
Оценивать качество договора по шкале 0–100 и формировать краткий вывод о рисках/пробелах/рекомендациях.
Сохранять результаты анализа в структурированном виде (таблица, JSON, CSV) и предоставлять отчёт в интерфейсе.
Обеспечить выбор модели ИИ («сильная»/«бюджетная») и режим автопромптинга для повышения точности на бюджетной модели.
2. Входные данные и поддерживаемые форматы
Форматы файлов: PDF, DOCX.
Источник файлов: локальная папка (путь указывается администратором/пользователем) или загрузка через интерфейс.
Набор параметров для проверки: настраиваемый список (чекбоксы/перечень) на отдельной странице настроек.
Дополнительный промпт: текстовое поле на странице настроек, которое передаётся в LLM вместе с содержимым договора.
Папка для сохранения результатов: путь указывается на странице настроек.
3. Функциональные требования
3.1. Страница настроек (отдельная вкладка/страница)
На странице должны быть:

Выбор параметров для анализа: список параметров с чекбоксами. По умолчанию — набор для договоров аренды (см. раздел 16). Возможность добавлять/удалять параметры.
Поле «Дополнительный промпт»: текстовое поле с подсказкой. Сюда можно вписать специфические требования (например, «Проверь, есть ли условие о конфиденциальности и как оно сформулировано»).
Выпадающий список «Модель ИИ»: варианты «Сильная модель», «Бюджетная модель».
Чекбокс «Включить автопромптинг»: при активации система делает 3–5 последовательных проходов с уточнением промпта.
Путь к папке с договорами: текстовое поле или выбор папки.
Путь для сохранения результатов: текстовое поле/выбор папки.
Кнопка «Сохранить настройки»: сохраняет конфигурацию в БД/файл конфигурации.
Кнопка «Проверить подключение/доступ к папкам»: валидация прав на чтение/запись.
Индикатор ожидаемой стоимости/скорости (текстовая подсказка): «Бюджетная модель — быстрее и дешевле; автопромптинг повышает точность, но увеличивает время и стоимость».
3.2. Страница анализа (основная рабочая область)
Список файлов в папке: таблица (имя файла, тип, размер, дата).
Кнопки действий:
«Запустить анализ выбранных файлов» (мульти‑выбор чекбоксов).
«Анализировать все файлы в папке».
«Скачать отчёт по результатам» (CSV/JSON/Excel‑like таблица).
«Параллельный тест (сильная vs бюджетная)» — для валидации качества (только для пилота/проверки).
Статус обработки: прогресс‑бар/индикатор, статусы: «в очереди», «в обработке», «готово», «ошибка».
Результаты по каждому файлу:
Оценка качества (число 0–100).
Статус по каждому параметру: «найдено», «не найдено», «частично найдено», «неясно».
Краткий вывод ИИ (1–3 предложения) о рисках/пробелах.
Ссылка/кнопка «Показать детали» (развёрнутый разбор с цитатами/фрагментами текста).
3.3. Детализация результатов (по кнопке «Показать детали»)
Для каждого договора выводить:

Список параметров и найденные фрагменты текста (с указанием страниц/разделов, если возможно).
Выявленные риски и пробелы.
Рекомендации по доработке (в виде нумерованного списка).
Промпт, который использовался для этого анализа (для воспроизводимости).
Промежуточные результаты автопромптинга (если включён) — для аудита спорных случаев.
4. Специфичные параметры для договоров аренды
В чекбоксы по умолчанию включить следующие группы параметров:

Стороны и полномочия: реквизиты (ИНН, ОГРН/паспортные данные), полномочия подписанта (устав/доверенность).
Предмет договора: адрес, площадь, кадастровый номер, этаж, схема/техплан (если часть помещения), целевое назначение.
Существенные условия: размер арендной платы, порядок и сроки внесения, срок действия договора, индексация/привязка к инфляции.
Права и обязанности: капитальный и текущий ремонт, содержание имущества, доступ к объекту, использование по назначению.
Ответственность и штрафы: неустойки, пени, баланс санкций.
Особые условия: обеспечительный платёж (депозит), неотделимые улучшения, субаренда, вывески, общее имущество.
Расторжение: условия досрочного выхода, нарушения, штрафные санкции.
Дополнительные риски: состояние имущества при передаче/возврате, пожарные риски, двусмысленные формулировки.
5. Логика автопромптинга (3–5 проходов)
Алгоритм:

Проход 1 (базовый анализ): система отправляет документ + базовый промпт + пользовательский доп. промпт. Получает первичный JSON с параметрами и выводами.
Выделение слабых мест: на основе первичного ответа система автоматически формирует список «неясно/частично найдено» и проблемных зон.
Проходы 2–5 (уточняющие): для каждой проблемной зоны генерируется уточняющий промпт (примеры — в разделе 17).
Агрегация результатов: финальный JSON формируется из всех проходов: приоритет у более поздних ответов; если разные проходы дают противоречивые статусы — система ставит «неясно» и прикладывает цитаты из обоих ответов для ручной проверки.
Лимиты: максимум 5 проходов; если за 3 прохода статус стабилизировался (не меняется), автопромптинг останавливается досрочно.
Хранение: для каждого файла сохраняются все промежуточные JSON (по проходам) — это нужно для аудита и разбора спорных случаев юристами.

6. Контроль соответствия результатов «сильная vs бюджетная» (95–98%)
Метрики качества
Согласованность по параметрам: доля совпадающих статусов («найдено/не найдено/частично/неясно») между результатами сильной модели и бюджетной (с автопромптингом) — целевой показатель ≥ 95%.
Согласованность выводов: совпадение ключевых рисков и рекомендаций (по смыслу, не по формулировкам) — ≥ 98%.
Доля «неясно»: не более 5% параметров в режиме «бюджетная + автопромптинг» должны оставаться в статусе «неясно».
Процедура валидации
На выборке 50 договоров (разных типов аренды) запустить параллельный анализ:
Вариант A: сильная модель, 1 проход.
Вариант B: бюджетная модель, автопромптинг 3–5 проходов.
Юридические эксперты проводят выборочную проверку расхождений (топ‑10% по количеству расхождений).
По итогам формируется отчёт: процент совпадения, список типов расхождений, причины.
При падении метрик ниже 95% — корректируется базовый промпт и логика автопромптинга.
Техническая реализация контроля
Режим «Параллельный тест»: отдельная кнопка для одновременного запуска двух вариантов на одном наборе файлов.
Отчёт «Сравнение моделей»: таблица с колонками: файл, параметр, статус (сильная), статус (бюджетная), совпадение/расхождение, комментарий ИИ, комментарий юриста.
Автоматические алерты: если доля расхождений по выборке > 5%, система выводит предупреждение администратору.
7. Технические требования
Язык/стек: любой современный стек (Node.js/Python/Go + React/Vue/Angular), главное — чёткое разделение API и UI.
Извлечение текста:
PDF: PDFium/Poppler/PyMuPDF.
DOCX: python‑docx/аналоги.
LLM‑интеграция:
Вызов LLM через API (я работаю на базе семейства моделей Alice AI) с передачей промпта и текста документа.
Промпт формируется динамически: базовый шаблон + пользовательский дополнительный промпт из настроек.
Обработка длинных документов: чанкинг текста (размер чанка 1000–2000 токенов), анализ по чанкам, агрегация результатов.
Хранение результатов: БД (PostgreSQL/SQLite) или JSON‑файлы в указанной папке.
Безопасность:
Доступ по логину/паролю (минимум 2 роли: администратор, пользователь).
Логирование действий (кто, когда, какие файлы анализировал).
Конфиденциальные данные не должны храниться дольше необходимого; предусмотреть возможность очистки.
8. Пример базового промпта (шаблон)
Проанализируй договор аренды и проверь наличие следующих параметров: стороны, предмет (адрес, площадь, кадастровый номер), срок аренды, размер и порядок внесения арендной платы, индексация, капитальный и текущий ремонт, ответственность сторон, штрафные санкции, обеспечительный платёж, условия расторжения, неотделимые улучшения.
Для каждого параметра укажи: найдено/не найдено/частично. Если найдено — приведи 1–2 коротких цитаты (не более 20 слов) с указанием раздела/страницы.
Оцени качество договора по шкале 0–100 и дай 3–5 конкретных рекомендаций по улучшению формулировок и закрытию рисков.
В конце выведи список параметров и статусов в виде JSON.

Пользователь добавляет в поле «Дополнительный промпт» свои уточнения, которые добавляются к этому шаблону.

9. Пример логики уточнения в автопромптинге
Если после Прохода 1 параметр «штрафы» имеет статус «частично» и нет цитат, система автоматически формирует промпт для Прохода 2:

«Ты ранее указал, что параметр “штрафы” найден частично. Перечитай разделы, где упоминаются санкции, неустойки, пени, ответственность. Ответь строго по формату:

Статус: найдено / не найдено / частично / неясно.
Если “найдено” или “частично”: приведи ровно 2 цитаты (до 20 слов каждая) с указанием раздела/страницы.
Если “неясно”: укажи, какой именно информации не хватает для однозначного вывода.
Не добавляй общих рассуждений — только факты и цитаты.»

11. Сценарии использования
Ежедневная проверка новых договоров: юрист загружает/указывает папку, запускает анализ, быстро просматривает статусы и фокусируется на проблемных договорах.
Аудит архива: анализ большого набора старых договоров для выявления типовых пробелов.
Контроль качества перед согласованием: быстрая проверка черновиков перед отправкой на внутреннее согласование.
Валидация качества ИИ: использование режима «Параллельный тест» для проверки соответствия результатов сильной и бюджетной моделей.
12. Ограничения и риски
ИИ не заменяет юридическую экспертизу: результаты — вспомогательный инструмент.
Для сложных/нестандартных договоров возможны ложные срабатывания/пропуски — обязательно предусмотреть ручной пересмотр.
Длинные договоры требуют чанкинга и аккуратной агрегации результатов.
Юридические формулировки могут быть неоднозначными — в таких случаях система должна ставить статус «неясно» и приводить фрагменты текста для проверки человеком.
13. План пилота (MVP)
Реализовать извлечение текста из PDF/DOCX.
Реализовать базовый промпт и получение JSON‑результатов от LLM.
Реализовать страницу настроек (параметры, промпт, папки, выбор модели, автопромптинг).
Реализовать интерфейс анализа и отображения результатов.
Реализовать логику автопромптинга и хранение промежуточных результатов.
Провести тестирование на 20–30 договорах аренды, собрать обратную связь юристов, скорректировать промпт и логику агрегации.
Запустить валидацию качества (сравнение сильной и бюджетной моделей) на выборке 50 договоров.
14. Влияние на производительность и стоимость
Бюджетная модель + автопромптинг (3–5 проходов) может быть сопоставима по стоимости с 1–2 проходами сильной модели, но даёт более предсказуемый результат на типовых договорах аренды.
Для длинных договоров (>30 страниц) автопромптинг рекомендуется только для выбранных параметров (по чекбоксам), а не для полного переразбора всего документа.
В UI предусмотреть предупреждение: «Автопромптинг увеличивает время обработки в 3–5 раз и стоимость пропорционально числу проходов».
15. Обновлённые критерии точности для пилота (с учётом автопромптинга)
Полнота обнаружения параметров (бюджетная + автопромптинг): ≥ 92%.
Точность классификации (бюджетная + автопромптинг): ≥ 96%.
Соответствие сильной модели (по статусам параметров): ≥ 95%.
Качество рекомендаций (полезность по оценке юристов): ≥ 80%.
Среднее количество проходов автопромптинга на договор: 3,5 (цель — стабилизация за 3–4 прохода).
16. Дополнительные рекомендации по UX для юристов
Метка «Профиль проверки»: добавить поле «Для арендатора» / «Для арендодателя». Дополнительный промпт можно строить с учётом этой метки: «Проанализируй договор с точки зрения арендатора. Какие условия создают для него повышенные риски?»
Визуализация «красных флагов»: в таблице результатов выделять цветом параметры со статусами «не найдено» и «частично», а также выводить краткую формулировку риска прямо в строке.
Экспорт отчётов: предусмотреть выгрузку не только CSV/JSON, но и краткого PDF‑отчёта для передачи руководству (с оценкой качества, списком рисков и рекомендациями).
17. Примеры уточняющих промптов для автопромптинга по аренде
Для предмета договора: «Перечитай раздел о предмете. Добавь в вывод, какие именно детали (площадь, кадастровый номер) отсутствуют, и предложи формулировку для устранения риска».
Для ответственности: «Проанализируй этот пункт ещё раз. Есть ли риск, что при споре суд истолкует его не в пользу одной из сторон? Приведи пример».
Для улучшений: «Прописаны ли в договоре порядок согласования и механизм возмещения затрат на неотделимые улучшения? Если нет — укажи, какие риски это создаёт».
