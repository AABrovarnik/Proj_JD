# Состояние проекта

Обновлено: 2026-10-15

## Текущий этап

Основной этап — итеративная настройка дополнительного промпта для бюджетной модели. Версия v1 проверена быстрым сравнением всех 9 загруженных договоров: по 7 договорам обе модели вернули оценки, на них обнаружено 15 расхождений по 70 параметрам. Для договора №8 бюджетный ответ завершился ошибкой, для №9 обе модели недоступны по сетевым ошибкам. Паритет не достигнут и не подтверждён.

## Восстановленная история работ

- Собран локальный интерфейс анализа договоров в пастельной голубой и салатной гамме; выявленные нарушения визуально выделяются контрастно. Есть отдельные страницы анализа, настроек и сравнения.
- Добавлены загрузка и извлечение текста PDF/DOCX, анализ по параметрам ТЗ, результаты/экспорт и тестовые договоры в `docs/договоры_Аренды`.
- Подключены базовый и дополнительный промпты из ТЗ; дополнительный промпт сохраняется в настройках.
- Добавлены профили LLM OpenAI / Alice / Local Mock и пары сильной/бюджетной моделей; ключи можно вводить в защищённом поле и хранить локально в зашифрованном виде. Подготовлен `.env.example`.
- Реализованы скрытие панели входа после авторизации, показ входа после выхода и очистка сохранённых ключей при смене логина.
- Создано сравнение сильной и бюджетной моделей по каждому договору и параметру; сильная модель может предложить улучшение дополнительного промпта.
- Добавлены timeout LLM-запроса (по умолчанию 120 секунд), быстрый режим без refine, refine только спорных параметров и прогресс по договорам в UI.
- Добавлены строгая проверка структуры результата и диагностические ошибки вместо принятия неполного ответа за корректную оценку.
- Добавлены длительность и usage токенов для базового вызова каждой модели в сравнении; метрики видны на странице сравнения, время сохраняется и при ошибке модели.
- Текущий дополнительный промпт заменён с узкой проверки расторжения/штрафов на универсальные критерии для всех 10 параметров. Он согласован со статусами схемы `found` / `partial` / `not_found` / `unclear`, сохранён в настройках и зафиксирован в снимке сравнения.
- Сформирован чек-лист передачи результата: `docs/ЧЕК_ЛИСТ_ПЕРЕД_СДАЧЕЙ.md`.
- Подготовлен `scripts/publish-github.ps1`: проверяет ветку/remote, запускает preflight, исключает секреты и локальные договоры, показывает staged diff и требует явного подтверждения commit; push выполняется только с `-Push`. Исправлено определение корня проекта через `$PSScriptRoot`, чтобы избежать искажения кириллицы в выводе Git. Для совместимости с PowerShell перенесена обработка native stderr внутрь `Invoke-Git`: предупреждения Git о LF/CRLF не прерывают сценарий, фактические ошибки определяются по exit code. PowerShell-синтаксис, `-DryRun`, обработка вывода `git diff --check` и `npm run preflight` проверены 2026-10-15; обе попытки пользователя остановились до staging, индекс чист, commit/push не запускались.
- В локальном Git есть тег `v0.1.0` на `main` (`origin/main`) и коммит подготовки changelog MVP. Это подтверждает локальные refs, но не проверяет содержимое GitHub Releases сейчас.

## Диагностика LLM из истории чата

- При сравнении пяти договоров возникали пустые ответы; затем проверку сузили до договора №1.
- Короткий запрос бюджетной модели ранее завершился примерно за 3,1 секунды с usage 26 токенов; полный прямой запрос по документу — примерно за 38,7 секунды, usage 6 424 токена.
- Тот полный ответ не стал корректной оценкой в приложении: нормализатор не сопоставил названия параметров, показал `unclear` и выдал недостоверный балл 25%. Этот балл не использовать.
- В более позднем прогоне сильная модель дала 78%, бюджетная завершилась `ECONNRESET`. Ключ/доступность endpoint и короткий запрос бюджетной модели проверялись отдельно, но устойчивость длинного запроса не доказана.
- В истории отмечались также `fetch failed` и сброс соединения. Причина на стороне OpenAI или промежуточной сети окончательно не установлена.
- После восстановления работы `npm run preflight` сначала не прошёл: сервер не слушал порт `3000`. Приложение запущено из текущего checkout; повторный preflight прошёл.
- Первый прогон после возобновления (80%/65%) обслуживался старым процессом без новых метрик; считать его диагностическим, не использовать как подтверждённую оценку.
- Повторный быстрый прогон договора №1 на обновлённом сервере завершился без технических ошибок: всего 133,1 с; сильная `gpt-6.1-sol` — 55%, высокий риск, 86,9 с, 8 191 токен (2 961 вход / 5 230 выход); бюджетная `gpt-6-luna` — 68%, средний риск, 32,9 с, 6 249 токенов (2 961 вход / 3 288 выход). Результат содержит все 10 параметров и 8 расхождений. Токены refine и рекомендации промпта не включены; прогон был быстрым, без refine.
- С промптом v1 быстрый прогон договора №1 завершился без технических ошибок за 139,1 с: сильная модель — 57%, высокий риск, 86,4 с и 8 337 токенов (3 369 вход / 4 968 выход); бюджетная — 50%, высокий риск, 39,2 с и 7 259 токенов (3 369 вход / 3 890 выход). Расхождений стало 3 из 10: стороны (`found`/`partial`), индексация (`found`/`partial`), расторжение (`unclear`/`partial`). Оценки и цитаты сохранены на `/compare`.
- Сильная модель предложила следующую точечную итерацию: не снижать статус сторон из-за отсутствия реквизитов/подписей; различать для индексации явный запрет, отсутствие и неполный механизм; для расторжения не подменять неоднозначность частичной полнотой. Эта рекомендация сохранена у результата v1, ещё не перенесена в настройки.
- 2026-10-14 выполнен быстрый прогон всех 9 договоров с v1, без refine. Завершён за 16 мин 16 с; обе модели успешно оценили договоры №1–7, сильная также оценила №8. Средний балл на успешно оценённых документах: сильная — 58,5% (8 договоров), бюджетная — 57,3% (7 договоров); эти средние рассчитаны по разным наборам и напрямую не сопоставимы. На общих №1–7 найдено 15 различий статусов из 70 параметров. Технические сбои: бюджетная модель на №8 (`terminated`); обе модели на №9 (`UND_ERR_CONNECT_TIMEOUT` / `ENOTFOUND`). Всего учтено 113 855 токенов базовых успешных вызовов; usage рекомендации промпта не учтён. Сильная модель не смогла сформировать рекомендацию v2 из-за сетевого таймаута. Результат сохранён в `/compare` (comparison id `cmp_1791992179038_tjljpy`).
- Usage вызова сильной модели, который формирует рекомендацию промпта, отдельно не учитывается. Показанные токены относятся к базовому анализу моделей; общий runtime включает рекомендацию.
- Проверены `node --check src/server.js`, `node --check public/compare.js` и `npm run preflight` — preflight прошёл на актуальном сервере. Модели не запускались тестом preflight; LLM-прогон выполнен отдельно выше.

## Открытые проблемы и границы проверки

- Версия v1 дала 15 расхождений на общих оценённых договорах №1–7; требуется разбор конкретных строк и цитат. Средние баллы рассчитаны на разных выборках из-за ошибок №8 и №9.
- Прогон по всем договорам выявил сетевую нестабильность бюджетной модели и OpenAI: №8 — `terminated`, №9 — DNS/connection timeout; не считать эти документы оценёнными обеими моделями.
- Сильная модель не сформировала улучшение промпта после прогона из-за `UND_ERR_CONNECT_TIMEOUT`; дополнительный вызов рекомендации надо повторить отдельно после проверки сети.
- Сильная модель — полезный компаратор, но не юридическая ground truth.
- Предыдущие 80%/65% были получены старым сервером и не должны смешиваться с текущим экспериментом.
- Нужно проверить обработку длинных LLM-запросов бюджетной моделью и отобразить понятную причину/статус при сетевом reset.
- Проверить соответствие ответа модели, OpenAI strict schema, серверной JSON Schema и нормализатора, включая точное сопоставление параметров и `extractedValues`.
- 2026-10-14 после прогона `npm run preflight` прошёл; авторизация, `/api/secrets/status`, `/api/llm/profiles`, `/api/comparisons` проверены. Страница `/compare` возвращает HTTP 200. Preflight сообщил только ожидаемое предупреждение: ключи отсутствуют в env, в этом запуске они были доступны через настройки приложения.
- Деплой в серверную песочницу не выполнен; производственная готовность не подтверждена. Упоминание «Теслы» осталось без установленного исполнителя/сервиса.
- Локальный тег `v0.1.0` есть, но отдельную актуальную проверку страницы GitHub Release не проводили.
